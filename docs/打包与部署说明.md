# NetToolBox 打包与离网部署说明

> 受众：负责打包与现场分发的执行者 ｜ 更新时机：打包链路或部署方式变更时。
> 功能演进历史看 [CHANGELOG.md](../CHANGELOG.md)；文档体系索引见 [README.md](README.md)（docs 下）。

> 离网网络运维工具箱（网络设备 + Linux）· 单文件 exe · U 盘拷贝即用
> 本工具**不含任何终端/SSH/串口/联网功能**，命令的执行者永远是外部 Xshell / SecureCRT。

---

## 一、打包环境要求（在**联网开发机**上执行）

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 7 SP1 / 10 / 11（64 位） |
| Python | 3.9 及以上（推荐 3.9 ~ 3.12） |
| 依赖 | `PyQt5`、`pyinstaller` |
| 源码目录 | 必须包含 `app/`（main.py / db.py / renderer.py / ui_*.py / seed_data/）与 `scripts/build_exe.py` |

```bash
pip install PyQt5 pyinstaller
```

---

## 二、一键打包（推荐）

```bash
python scripts/build_exe.py
```

`build_exe.py` 会依次完成：

1. **打包前检查**：PyQt5 / PyInstaller 是否安装、`app/` 源文件是否齐全、语法能否编译、`seed_data` 是否有厂商文件
2. **种子库质检**：自动调用 `python app/main.py --validate-seed`，逐条校验全部条目 + 排查树 + 报错字典的参数、结构与样例自测、占位、端口展开（不通过则中止打包）
3. **调用 PyInstaller** 打出单文件 exe（中间产物定向仓库根 `build/`、`dist/`）
4. **收拢产物**到 `dist_package/`（exe + 纯净种子库 + check_db.py + seed_data/，命名 `NetToolBox_v<版本>.zip`）
5. 打印 U 盘部署步骤与验证清单

只做检查不打包：

```bash
python scripts/build_exe.py --check
```

> 纪律：让位机制用 `.trash-<时间戳>`（构建成功后自动清理），**禁止 `.stale-*`**；详见根目录 [AGENTS.md](../AGENTS.md)。

## 三、手动打包命令（等价形式）

需要自定义时可直接用：

```bat
pyinstaller --noconfirm --clean --onefile --windowed ^
  --name "NetToolBox" ^
  --add-data "app/seed_data;seed_data" ^
  app\main.py
```

要点说明：

| 参数 | 作用 |
|---|---|
| `--onefile` | 打成单个 exe，U 盘拷贝即用 |
| `--windowed` | 不弹黑色控制台窗口（GUI 程序必须加） |
| `--add-data "app/seed_data;seed_data"` | 把种子库塞进 exe，首次运行可"释放"到库里。**Windows 用分号 `;` 分隔，Linux/macOS 用冒号 `:`** |
| `--name NetToolBox` | 产物名 |

`build_exe.py` 额外加了若干 `--exclude-module`（QtWebEngine / QtQuick / tkinter 等用不到的大块），
可以把产物从 ~60MB 压到 **约 38MB**。

## 四、产物与"数据分离"原则

打包后只产生**一个** exe，但运行期涉及**两个位置**：

```
U 盘:\NetToolBox\
├── NetToolBox.exe        ← 程序（约 38MB，含内置种子库）
├── command_lib.db       ← 命令库（首次运行自动生成，★ 你的数据在这里）
└── seed_data\           ← 可选：现场自加的厂商条目（优先于 exe 内置的那份）
    ├── cisco.json
    └── placeholders\    ← 待补厂商目录
```

| 文件 | 是否打进 exe | 说明 |
|---|---|---|
| `command_lib.db` | **否** | 永远生成在 exe 同目录。改命令库、加条目**不需要重新打包 exe** |
| `seed_data/*.json` | 是 | 打进 exe 供首次导入；若 exe 同目录也有 `seed_data`，**优先读同目录那份** |

> 这条设计就是为了"改命令库不用重新打包"：团队在 U 盘上直接改 `seed_data/*.json`
> 或用程序里的"命令库管理器"改完导出 `.nlb`，都不用碰开发机。

## 五、U 盘部署（三步）

**第 1 步**　把 `dist_package\` 内的 exe 拷到 U 盘任意目录（建议单独建个 `NetToolBox` 文件夹）

**第 2 步**　双击运行 → 首次启动弹出引导（检测到种子库文件后询问是否导入）：

```
┌─ 首次启动 · 请先读这段 ─────────────────────────┐
│ 命令库已就绪，检测到 N 个种子库文件，是否导入？   │
│  [重要] 内置命令全部为「未验证」，未经真机验证前    │
│         请勿直接用于生产设备                      │
│         [导入内置种子库]  [先空库使用]            │
└──────────────────────────────────────────────┘
```

选「导入内置种子库」→ 自动在 exe 同目录生成 `command_lib.db` → 弹出**上车指引**
（显示导入了多少条、多少厂商、多少场景，以及三步上手与验证提醒）。

**第 3 步**　换电脑时：**把整个目录拷过去**（exe + db 一起）。
只拷 exe 会得到一份空库，现场积累的条目就丢了。

## 六、首次启动会走的三种分支

| 情况 | 程序行为 |
|---|---|
| 无 db 文件（全新 U 盘） | 自动建空库 → 弹**首次启动引导**（含免责声明）→ 可选导入种子库 → 显示上车指引 |
| 有 db 但一条条目都没有（上次选了"空库使用"） | 提示"检测到 N 个种子库文件，是否现在导入" |
| U 盘为写保护状态 | 自动进入**只读模式**：可搜索/浏览/复制，禁止新建/编辑/删除/标记验证/导入，标题栏与左下角显示 `[只读]` |

## 七、交付前必跑的三个自检

```bash
python app/main.py --selftest        # 基础自检（数据层 + 渲染层）
python app/main.py --validate-seed   # 种子库质检（条目 + 排查树 + 报错字典 + 分析器规则）
python app/main.py --audit-offline   # 离网审计：确认运行时代码零网络依赖（交付门槛）
```

exe 同样支持（无控制台时结果写入同目录 `NetToolBox_cli.log`）：

```bash
NetToolBox.exe --validate-seed
NetToolBox.exe --audit-offline
```

**`--audit-offline` 做什么**：用 AST 解析运行时代码文件的全部 import，
并扫描真实代码行（自动排除字符串字面量与注释）里的 `urlopen(`/`requests.`/`socket.`/
`http(s)://` 等特征 —— 确认本工具在离网环境中**不会产生任何出网行为**。
`build_exe.py`（开发工具，不随交付运行）单独列出、不计失败。

## 八、遇到崩溃怎么办（现场排障）

程序（尤其 exe）出错时，**会自动在程序同目录留下两个日志**，先看它们再反馈：

| 文件 | 内容 |
|---|---|
| `NetToolBox_error.log` | 界面/Python 异常堆栈（带行号，直接定位问题） |
| `NetToolBox_cli.log` | 每次启动的参数与 CLI 命令输出（自检结果也在这里） |

**CLI 自检结果看不到怎么办**：`--windowed` 打包的 exe 没有控制台，输出会消失 ——
已做输出分流，`NetToolBox_cli.log` 里完整留档，直接看文件即可。
（中文控制台编码坑已修复：CLI 输出只用 ASCII 安全标记 `[OK]/[X]/[!]`，编码策略 replace。）

## 九、常见问题（现场高频）

| 现象 | 原因与处理 |
|---|---|
| 双击 exe 没反应 | 先看同目录有没有 `NetToolBox_error.log`；再看是否被杀软拦截（见下） |
| 界面起来但左侧树是空的、一条命令都没有 | 首次引导时选了「先空库使用」。菜单 帮助 →「首次启动提示」可重新导入 |
| 换电脑后条目全没了 | 只拷了 exe 没拷 `command_lib.db`。把整个目录拷过去即可 |
| 提示"只读模式"、编辑按钮灰掉 | U 盘写保护开关打开着（或目录无写权限）。关掉写保护后重开程序 |
| 杀毒软件报毒/拦截 | PyInstaller 单文件 exe 的常见误报。加白名单，或让 IT 用公司流程签名后分发 |
| exe 启动要等 3~8 秒 | 单文件模式需先解压到临时目录，属正常现象；介意可用 `--onedir` 打包成文件夹版 |
| 改了几条命令，要不要重新打包 | **不需要**。程序里改完即可；要给团队同步就导出 `.nlb` 发出去 |
| 想让团队都拿到我新增的条目 | 命令库管理器 →「导出 .nlb」→ 同事「导入 .nlb」，按 UUID 合并去重，冲突保留"已验证"那条 |

## 十、升级与迁移

| 场景 | 操作 |
|---|---|
| 程序升级（换新版 exe） | 只替换 `NetToolBox.exe`，**保留** `command_lib.db` 与 `seed_data/`；启动后从 帮助 →「首次启动提示」重新导入种子库，新版新增的条目会按 UUID 合并进来，现场验证过的条目不会被覆盖成未验证 |
| 换 U 盘 | 整目录拷贝（exe + db + seed_data） |
| 库损坏（掉电/拔出） | 程序会自动把损坏文件改名为 `command_lib.db.corrupt-<时间>.bak` 并重建空库，不会起不来；原文件可事后尝试修复 |
| 团队同步条目 | 导出/导入 `.nlb`，或直接交换 `seed_data/*.json` |
| 老库 slug/duration 归一化 | `python scripts/migrate_to_slug.py --dry-run` 先预览，去掉 `--dry-run` 执行（自动备份 db；同时归一化 `seed_data/*.json` 的 vendor/os_family/platform/duration） |

## 十一、安全与合规说明

- 全项目**不 import 任何网络模块**（requests / urllib / socket / paramiko / telnetlib…），
  无更新检查、无在线资源、无遥测，符合隔离网安全审计要求
- 程序**不建立任何网络连接**，不向任何外部地址发送数据
- 命令库文件（`command_lib.db`）与导出文件（`.nlb` / `.txt`）均为本地明文，
  内含设备配置片段与操作留痕，**请勿放到共享目录或外发**，按内部资料管理
- 条目中的口令类参数 default 均为空值（现场必填），示例值仅为格式提示，**必须现场替换**，
  不要直接下发到设备
