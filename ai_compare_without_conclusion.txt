

## 结构化诊断：192.168.20.0/24 不通

### 当前状态分析

| 步骤 | 执行内容 | 观察结果 | 结论 |
|------|---------|---------|------|
| 1 | `show ip route 192.168.20.0` | `% Network not in table` | 路由表中无此网段路由 |

---

### 推荐诊断步骤（按顺序执行）

#### 步骤 1：确认故障范围 — 从哪侧查起

**先明确：这台 C2960X 是路由器的角色还是交换机的角色？**

- 若作为**三层网关**：192.168.20.0/24 可能应配置在本机的 VLAN 接口上
- 若作为**上游转发设备**：需要确认是否有到达该网段的下一跳路由

```cisco
! 查看本机所有三层接口状态
show ip interface brief
适用厂商：Cisco ｜ OS 版本：Cisco IOS（C2960X）
```

**判断依据：**
- 若看到 `VLANxxx` 或 `interface 192.168.20.x` 相关接口 → 该网段应由本机直连承载，检查接口 IP 和状态
- 若本机无该网段接口 → 属于**缺少路由**，继续步骤 2

---

#### 步骤 2：确认直连网段与接口状态

```cisco
! 查看所有接口 IP 分配情况
show ip interface | include Vlan|Fast|Gig|Internet

! 查看接口物理状态（确认线缆/PoE 是否正常）
show interfaces status | include 192.168.20
适用厂商：Cisco ｜ OS 版本：Cisco IOS（C2960X）
```

**判断依据：**
- 接口 `down/down` → 排查物理层（线缆、对端设备、PoE）
- 接口 `up/up` 但无 IP → 需检查 VLAN 是否创建、SVI 是否启用
- 接口有 IP 但 `line protocol is down` → 检查 VLAN 是否激活、本端/对端封装是否一致

---

#### 步骤 3：确认对端可达性（关键）

```cisco
! Ping 默认网关或下一跳（替换为实际下一跳地址）
ping 192.168.20.1 source <本机出接口IP>

! traceroute 排查断点
traceroute 192.168.20.1
适用厂商：Cisco ｜ OS 版本：Cisco IOS（C2960X）
```

**判断依据：**
- `ping` 不通下一跳 → 链路层或直连路由有问题
- `ping` 通下一跳但业务不通 → 路由方向不对称，需检查回程路由
- `traceroute` 在某一跳停止 → 故障设备定位到此跳

---

#### 步骤 4：补齐静态路由（当前待执行步骤）⚠️

**风险提示：添加路由前必须确认下一跳地址正确，否则可能导致流量黑洞或路由环路。**

```cisco
! 查看现有路由表，确认下一跳规划
show ip route

! 添加静态路由（假设下一跳为 10.0.0.1）
ip route 192.168.20.0 255.255.255.0 10.0.0.1
适用厂商：Cisco ｜ OS 版本：Cisco IOS（C2960X）
未经真机验证，请先在维护窗口验证
```

**验证步骤：**
```cisco
! 确认路由已写入
show ip route 192.168.20.0

! 双向 ping 测试
ping 192.168.20.1 source <本机出接口IP>
```

### 决策树（依据输出判断下一步）

```
show ip route 192.168.20.0 → % Network not in table
        │
        ├─→ show ip interface brief 中有对应 VLAN/SVI 接口？
        │       ├─ 是 → 检查接口状态（步骤2）
        │       └─ 否 → 本设备不应承载该网段，继续↓
        │
        ├─→ show ip route 中有默认路由 0.0.0.0/0？
        │       ├─ 是 → 检查默认路由下一跳是否可达（步骤3）
        │       └─ 否 → 缺少默认路由，需补充
        │
        └─→ 确认下一跳地址后 → 添加静态路由（步骤4）
```

---

### 操作风险警告 ⚠️

| 操作 | 风险 | 缓解措施 |
|------|------|---------|
| `ip route` 添加静态路由 | 若下一跳错误，流量进入黑洞 | 添加前先 `ping` 测试下一跳可达性 |
| 未做备份修改配置 | 误操作导致全网中断 | 执行 `copy running-config startup-config` 前确认 |
| 在无维护窗口时操作 | 影响现网业务 | 建议在维护窗口内执行 |
